# Apple Music 播放链路技术档案（逆向 + 实测确认）

> 2026-09-11 通过读取 gamdl 3.8.5 源码 + 真实抓包验证得出。用于鸿蒙原生客户端实现。

## 一、完整六步流程

```
① POST https://play.itunes.apple.com/WebObjects/MZPlay.woa/wa/webPlayback
   headers: Authorization: Bearer <developerToken>
            Origin: https://music.apple.com
            Cookie: media-user-token=<userToken>
   body:    { "salableAdamId": "<歌曲ID>", "language": "en-US" }
   → { songList: [ { songId, assets: [ { flavor, URL, metadata } ] } ] }

② 在 assets 里挑一个 flavor（aac-web 对应 256kbps，如 "28:ctrp256"）
   → asset.URL 就是该音的「子清单 m3u8」

③ GET 子清单 → 解析 #EXT-X-KEY 的 URI
   → 形如 data:;base64,AAAAAB/wCWIAHUXEMbExUg==      ← 这就是 widevine_pssh

④ 用 widevine_pssh 生成 challenge：
   - 直接原样作为 license 请求的 uri 参数
   - 同时 reconstruct：
       b64 = pssh.split(",")[-1] → decode
       若 len(decoded) > 30  → 直接用 b64
       否则                  → WidevinePsshData(algorithm=1, key_ids=[decoded]).serialize()
   - 用设备私钥 RSA-SHA1 签 LicenseRequest → 包进 SignedMessage

⑤ POST https://play.itunes.apple.com/WebObjects/MZPlay.woa/wa/acquireWebPlaybackLicense
   （同样的三个 header）
   body: { "challenge": <base64(challenge)>,
           "key-system": "com.widevine.alpha",
           "uri": <第③步的 data:;base64,...>,
           "adamId": "<歌曲ID>",
           "isLibrary": false,
           "user-initiated": true }
   → { "license": "<base64 的 SignedMessage>" }

⑥ cdm.parse_license(license) → content key（一条 CONTENT 类型、16 字节 AES key）
   然后下载分片，按 CENC/SAMPLE-AES 规则用该 key 解密，拼成 m4a
```

## 二、认证（不需要 Apple Developer 账号）

| 凭证 | 获取方式 |
|---|---|
| **developerToken** | GET `https://music.apple.com` → 正则 `/(assets/index[~-][^/"]+\.js)` 拿 index.js 路径 → GET 它 → 正则 `"(eyJ[A-Za-z0-9\-_]+\.eyJ[A-Za-z0-9\-_]+\.[A-Za-z0-9\-_]+)"` 抓 JWT（约 70 天有效，实测 `iss=AMPWebPlay`） |
| **media-user-token** | 用户在应用内 Web 登录后取 cookie。**注意 domain 必须是 `.music.apple.com`**（Playwright 导出的是 `.apple.com`，需改写） |

## 三、Widevine 密钥派生的精确算法（来自 pywidevine）

```python
# context 构造
enc_context = b"ENCRYPTION"     + b"\x00" + license_request_bytes + (128).to_bytes(4, "big")
mac_context = b"AUTHENTICATION" + b"\x00" + license_request_bytes + (512).to_bytes(4, "big")

# 派生（key = session_key）
def derive(key, context, counter):
    return AES_CMAC(key, bytes([counter]) + context)

enc_key        = derive(session_key, enc_context, 1)
mac_key_server = derive(session_key, mac_context, 1) + derive(session_key, mac_context, 2)

# 校验：HMAC-SHA256(mac_key_server, oemcrypto_core_message + license_msg) == signature
# 解 key：AES-CBC(enc_key, iv=key_container.iv) 解 key_container.key，再去 PKCS7 padding
```

## 八、音频加密格式（2026-09-11 深挖，已用真实分片验证）

**子清单长这样**：
```
#EXT-X-KEY:METHOD=ISO-23001-7,URI="data:;base64,AAAAAB/wCWIAHUXEMbExUg=="
#EXT-X-MAP:URI="mzaf_A535824738.rmhq.aac.wa.mp4",BYTERANGE="1006@0"
#EXTINF:9.98458,
#EXT-X-BYTERANGE:324055@1006
mzaf_A535824738.rmhq.aac.wa.mp4
```

**关键点：整首歌就是一个 MP4 文件**（约 9MB），用 `#EXT-X-BYTERANGE` 切片，
不是传统的一堆独立 .m4s。所以下载可以：一次性拉整文件，或按 range 分段拉（便于显示进度）。

**加密参数（从真实 init segment + 首分片解析得到）**：

| 项 | 值 | 含义 |
|---|---|---|
| `schm.scheme_type` | `cenc` | AES-CTR（不是 cbcs/CBC） |
| `tenc.isProtected` | 1 | 加密的 |
| `tenc.default_Per_Sample_IV_Size` | **8** | IV 有效 8 字节 |
| `tenc.default_KID` | `000000001ff00962001d45c431b13152` | 与 `#EXT-X-KEY` 的 base64 完全对应 |
| `frma` | `mp4a` | 原始格式 AAC |
| `senc` | version=0, sampleCount=430，每 sample **16 字节 IV** | 430×16 = 6880 字节，与 senc box 大小精确吻合 |

**因此解密算法**：
```
对每个 sample：
  iv = senc 中该 sample 的 16 字节 IV 的前 8 字节 + 8 个 0x00  → 16 字节计数器
  明文 = AES_CTR_decrypt(content_key, iv, mdat 中该 sample 的密文)
sample 的边界从 moof/traf/trun 里读
```
没有 subsample（不存在部分明文的情况），整段 sample 数据都是密文。

**盒结构参考**：
```
init segment (前 1006 字节):
  ftyp → moov → trak → mdia → minf → stbl → stsd → enca → sinf → schm(cenc) → schi → tenc
media 分片:
  moof → mfhd / traf(tfhd, tfdt, senc, saiz, saio, trun) + mdat
```
