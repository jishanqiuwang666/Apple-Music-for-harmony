# 播放详情页 · 歌词视觉对齐 Apple Music（2026-10-17 第二轮）

用户提供了 31s 的官方录屏（720×1554，iPhone 15 Pro Max，方大同《爱爱爱》），
要求「歌词动画、灵动感、光效感、上下渐隐模糊」向官方靠拢。这一轮**全部按录屏逐像素量测**来做，
不凭印象调参。

---

## 一、量测方法（可复用）

```bash
# 1. 抽帧（432 宽 ≈ 原机 430pt，1:1 便于直接读数值）
ffmpeg -ss 19 -i am.mp4 -frames:v 1 -vf scale=432:-1 t19.png
# 2. 逐行找「文字带」：对每行取 max - median（对比度），阈值以上即文字
# 3. 每带算 α = (peak - 局部背景) / (255 - 局部背景)
#    背景必须取同一行右侧空白区，不能用整图中位数（背景是渐变，会差 0.1 以上）
```

得到的关键数字（430pt 宽的 iPhone，1pt ≈ 我们 0.9vp）：

| 项 | 官方实测 | 我们（388vp 宽） |
|---|---|---|
| 当前行首行中心 | 屏高 **25%**（233/932） | 25% ✔ 原本就对 |
| 行内行距 / 段落行距 | 47pt / 84pt | 42vp / 75vp ✔ |
| 字宽（字径） | 39pt/字 | 34~35fp ✔ |
| **当前行字重** | **Bold** | 原来全 Bold ❌ |
| **其它行字重** | **Regular** | 原来全 Bold ❌ |
| **灰字不透明度** | **α ≈ 0.19~0.23（与距离无关）** | 原来 0.36 ❌ |
| **当前行未唱的字** | **同一档灰 α≈0.20** | 原来 0.55 ❌ |
| **已唱完的上一行** | **立刻回灰**（一页只有一行白） | 原来保持纯白 ❌ |
| 模糊 | 以当前行为中心双侧景深，近处清晰、远处糊成一团 | 原来只有边缘 14px、中段无模糊 ❌ |
| 顶部 | 当前行上方只剩一条极淡残影（α≈0.1），2 行内归零 | 原来下限 0.62 ❌ |
| 底部 | 一直到 87% 屏高仍可见（模糊渐强），之后才消失 | 原来 56% 就开始收 ❌ |
| 背景 | 深色幕布（亮度 ~40/255） | 原来糊化封面偏亮（60~95）❌ |

> 结论一句话：**官方的「聚焦感」不是靠给当前行提亮，而是靠「整页只有当前行的已唱部分是纯白」**，
> 远近层次全部交给「渐隐 + 空间模糊」。这一条改完，观感立刻对上了。

## 二、改动清单

### `common`/`model/LyricVisual.ets`
- `LYRIC_DIM_ALPHA` 0.36 → **0.20**（附量测依据）。

### `features/player/view/AppleLyricsView.ets`（主要工作量）
1. **聚光灯效果**：`applyActive()` 里把「上一行」的 token 动画回 `LYRIC_DIM_ALPHA`；
   `resyncTokens()`（seek 跳变时）也改成「除当前行以外全部回灰」。
   原来唱过的行一直纯白，上半屏白花花一片 —— 这是最不像官方的一处。
2. **字重**：当前行 `FontWeight.Bold`，其余 `FontWeight.Normal`。
3. **景深模糊**：`linearGradientBlur` 半径 14px → **30px**，
   分段改成「以锚点为中心、±0.95 行为清晰平台、两侧线性变糊」；
   原来中段一大片 0 模糊，所以远近没有层次。
4. **上下渐隐**：改成锚点相对坐标 ——
   上：`((y-top)/(anchor-top))^0.62`（一行内几乎消失）；
   下：到 86% 行程才开始收 + 最后 34vp 快速归零。
5. **光效**：
   - 当前行已唱的字加 `textShadow`（radius 8 / 白 24%）做 bloom
     —— **只给 α>0.6 的字**，否则未唱的字会被整体抬亮（实测 α 0.20→0.36，白字还发虚）；
   - 新增「锚点柔光」层：一层静止的径向渐变（白 10%），换行时 `glow` 数值
     260ms 冲到 1.0 再 820ms 缓落 —— 这是「灵动感」里最便宜的一层
     （一次换行只动两下，不参与逐帧渲染）。
6. 译文行亮度跟着降档（当前行 0.5 / 其它 0.18）。

### `features/player/view/PhonePlaybackPage.ets`
- **歌词模式黑纱**：新增一层 `#000000` 遮罩，`opacity = lyrics × 0.46`
  （进歌词页淡入、退回封面页淡出）。官方歌词页本来就是深色幕布，
  不压暗的话 0.2 的灰字压在浅色封面上直接糊掉（真机截图实测背景亮度 60~95 → 35~55）。
- 歌词左右边距 30 → 32vp（官方实测 33vp）。

## 四、性能

| 项 | 代价 |
|---|---|
| 锚点柔光 | 1 个静止径向渐变层；换行时 2 次数值动画 |
| textShadow bloom | 只有可见的「已唱白字」节点（≤10 个） |
| linearGradientBlur 30px | 与原来同一条离屏模糊通道，只是半径变大（每帧固定一次，不随行数变化） |
| 字重切换 / 回灰动画 | 每次换行动一次（约每 3~5 秒一次） |

没有任何逐帧新增开销：心跳仍是 100ms 一次、只在换行/换字时动 UI。

## 五、复用的经验

1. **UI 对齐「官方感」先量数值**：把录屏抽成和原机 1:1 的帧，按行算 α 和位置，
   再回到自己屏幕按比例换算。这次一量就发现「我们 dim 0.36 vs 官方 0.20」这种关键差异，
   而这种差异靠肉眼是看不出来的（只会觉得「不太像」）。
2. **测背景必须用同行空白区**：整图中位数当背景会把 α 算偏 0.1 以上（背景是渐变 + 柔光）。
3. **`textShadow` 当 bloom 会污染同一行的其它字**：只给「已经变白的字」加，否则未唱的字会被抬亮。
4. **深色幕布是歌词页观感的一半**：官方歌词页的背景亮度只有封面页的 1/2，
   而且这层压暗必须跟着「进入/退出歌词页」动画，否则切换会突跳。

## 六、追加修复（同日第二轮：光晕生硬 / 字体光有分界线）

用户真机反馈两处观感崩坏：

1. **「背景的发光模糊有点生硬，能看到光线明显的边界是一个矩形」**
2. **「字体发光的最左侧明显有一个光的分界线」**

### 根因

| 现象 | 根因 |
|---|---|
| 矩形光块 | 光晕层是 `388×260` 的矩形盒子，`radialGradient({ radius: '200vp' })` —— **ArkUI 的 gradient radius 只接受「数字」或「百分比」，带单位的字符串 '200vp' 会失效** → 整个盒子退化成**一块半透明白矩形**，四边就是肉眼看到的「矩形光边界」 |
| 字体左侧竖向硬边 | bloom 用 `Text.textShadow()` 实现，而 **textShadow 是按 Text 节点裁剪的**；歌词每个字都是一个独立 Text 节点，最左侧那个字的阴影在自己的节点左边界被切掉 → 一条笔直的竖向分界线 |

### 修法

1. 光晕层改成**正方形盒子（460×460）+ `radius: '50%'`**（项目里 `Player.ets` 的播放条柔光就是这种写法，已验证）：
   圆的半径正好等于半边长，四条边中点 α = 0，无论百分比按宽还是按高解析都不会留边；
   边长比屏宽大 ⇒ 圆的可见外缘直接落到屏幕外。外面再套一层 `width('100%')` 的 Stack 把它水平居中。
2. **字发光整套删掉**：把官方录屏放大到像素级看，Apple 的当前行白字**是没有 halo 的**
   （只有视频压缩带来的一点点柔边）。所以既不用 textShadow（会裁边），也不做「整层模糊副本」
   （试过：即使降到 blur 4vp/α0.45 仍是明显的「霓虹感」）。
   现在当前行 = 纯白 Bold，无任何发光；「光效感」由**整页锚点柔光 + 深色幕布 + 纯白字本身**提供。
   顺带少了一层文字节点（每行 ~10 个），性能更好。

### 验证（真机 1260×2720 量测）

- 水平方向：在无文字的横向条带上扫相邻像素亮度差，**最大 5.5/255（≈2%，属 JPEG 噪声）**，无台阶 ⇒ 没有矩形边界。
- 竖直方向：活跃行上方 y=605 一行扫水平相邻像素，**最大跳变 1/255** ⇒ 左侧无分界线。
- 放大对比：当前行白字边缘干净，与官方录屏同款；灰字景深、锚点柔光保留。

### 复用经验

- **`radialGradient` 的 `radius` 别写单位**：用数字（视作 vp）或百分比；写 `'200vp'` 静默失效成纯色填充，
  症状是「一块看得见边的光斑」。
- **`textShadow` 是节点级裁剪的**：凡是「把一组文字拆成多个 Text 节点再逐个加阴影」的做法，
  在节点边界都会出现竖/横向硬边；要做发光要么整层模糊（会偏霓虹），要么干脆不做。
- 判断「有没有硬边」别靠眼睛：在无文字的条带上扫**相邻像素亮度差**，台阶 > 8/255 就说明有边。
